# 교사의 별자리

교사들의 공개 웹앱 허브를 모으는 타로 카드 아카이브입니다.

- 사이트: https://taehwan-shin.github.io/teacher-hub/
- 등록 안내와 공유 프롬프트: [CONTRIBUTING.md](CONTRIBUTING.md)
- 등록 요청: https://github.com/Taehwan-Shin/teacher-hub/issues

## Codex 한 번으로 등록 신청

배포된 허브 프로젝트를 Codex에서 열고 사이트의 **등록 프롬프트 복사** 내용을 붙여넣습니다. Codex가 공개 허브 정보를 확인해 Firebase에 접수하고 접수 번호·추적 링크를 안내합니다. 선생님의 GitHub Issue 생성 권한이나 브라우저 제출은 필요하지 않습니다. 배포 주소·정보가 없거나 실행 환경이 네트워크 승인을 요구하면 확인 단계가 생길 수 있습니다.

GitHub Actions의 **등록 접수와 자동 게시**가 약 10분 간격으로 대기 신청을 Issue로 전환합니다. GitHub 사정에 따른 지연·누락이 가능하며, 접수 즉시 카드가 게시되지는 않습니다. Issue 생성부터 자동 승인·게시까지 같은 실행에서 처리합니다. 상세 클라이언트 실행 방법은 [REGISTRATION_API.md](REGISTRATION_API.md)를 확인하세요.

자동 처리 실패 시 Actions에서 **등록 접수와 자동 게시 → Run workflow**를 실행합니다. 공개 저장소의 예약 실행은 장기간 활동이 없으면 GitHub가 비활성화할 수 있으므로 운영자가 상태를 확인해야 합니다. 등록 처리용 Firebase Secret 교체·중단 절차는 [backend/README.md](backend/README.md)에 있습니다.

## 자동 승인과 게시

Firebase 접수와 GitHub 직접 신청을 모두 자동 승인·등록합니다. 직접 작성한 Issue는 생성·재개·편집 이벤트로 처리하고, Firebase 접수는 약 10분 간격의 예약 실행 또는 Run workflow로 처리합니다. 운영자 승인 라벨을 붙일 필요가 없습니다. 서로 다른 신청이면 같은 주소도 별도 카드로 추가됩니다. 같은 Issue·접수 번호의 재실행은 카드를 추가하지 않습니다.

입력 형식·개인정보 패턴·공개 HTTPS 주소 검사는 유지합니다. 잘못된 형식이나 저장 후 수정된 신청은 보존하고 Actions Summary에 집계합니다. 저장된 카드 내용은 불변이며 수정은 새 신청서를 제출합니다. 공개 사이트의 목록에서 신청 내용이 실제 확인된 뒤 완료 댓글을 남기고 Issue를 닫습니다. 게시 실패 시 다음 주기 또는 Run workflow로 복구합니다.

이미 게시된 카드 제거는 원래 신청 Issue에 먼저 **등록취소** 라벨을 붙이고, 닫혀 있으면 다시 연 뒤 해당 라벨을 제거했다가 다시 붙입니다. 소유자 계정의 취소만 실행되며 취소 라벨이 있는 신청은 자동 등록에서 제외됩니다. 승인 라벨 제거만으로 카드는 삭제되지 않습니다.

## 로컬 실행

Node.js 24 이상에서 설치 없이 실행합니다.

```powershell
node scripts/build.mjs
node --test tests/*.test.mjs
node scripts/serve.mjs
```

주소: http://127.0.0.1:4188 . 서버는 loopback만 허용합니다. 종료는 Ctrl+C입니다.

## 구성

site/는 HTML·CSS·JavaScript와 직접 그린 SVG입니다. data/hubs.json은 승인된 공개 목록입니다. scripts/는 입력 검사·등록·완료 처리·정적 빌드를 담당합니다. .github/workflows/intake.yml은 접수·자동 등록·게시·완료를 처리하며, publish.yml은 소유자 취소 및 main 코드 변경 게시를 처리합니다. GITHUB_TOKEN의 등록 커밋은 push 워크플로를 다시 시작하지 않으므로 같은 워크플로에서 직접 게시합니다. 게시 작업을 직렬화하고 게시 직전 최신 main을 읽어 동시 등록 누락을 방지합니다.

카드는 큰 화면에서 5열, 화면 크기에 따라 4·3·2·1열로 표시됩니다. 커서가 있는 환경에서 2.8초 동안 서서히 3D 회전하며 동작 감소 설정은 효과를 끕니다. 검색·분류는 브라우저 메모리에서 처리합니다. 신청 프롬프트 복사가 막히면 직접 복사할 수 있습니다.

## 공개 피드백

카드 아래 **피드백 남기기 · 보기**를 누르면 로그인 화면 없이 익명으로 작성하고 즉시 공개합니다. 2~500자, 익명 연결당 5초에 한 번, 전체 댓글 영역에서 시간당 최대 100개입니다. 최근 20개를 표시하고 이전 댓글을 더 불러올 수 있습니다. 다른 사람의 최신 의견은 새로고침으로 확인합니다.

기존 일기장의 Firebase 프로젝트 `classroom-diary-098bae6e`에 분리된 댓글 컬렉션을 사용합니다. 공개 댓글에는 본문·서버 시각만 저장하며 이름·이메일·작성자 UID는 넣지 않습니다. 익명 연결 정보는 브라우저 메모리에만 남깁니다. 이메일·전화번호 등의 대표 패턴을 거부하지만 모든 자연어 개인정보를 자동으로 감지할 수는 없습니다.

댓글 아래 **삭제**를 누르고 공용 삭제 비밀번호를 입력하면 삭제할 수 있습니다. 이 비밀번호를 아는 사람은 누구나 모든 허브의 댓글을 삭제할 수 있으며 사이트에서 복구할 수 없습니다. 비밀번호는 Firebase 인증에서 검증하고 공개 코드에는 저장하지 않습니다. 운영자는 [Firebase 댓글 데이터](https://console.firebase.google.com/project/classroom-diary-098bae6e/firestore/databases/-default-/data)에서도 해당 댓글 문서만 삭제할 수 있습니다. 신고에는 댓글 시각을 적고 개인정보가 담긴 원문을 재게시하지 마세요.

일기장과 댓글의 전체 보안 규칙은 [backend/firestore.rules](backend/firestore.rules)에 보관합니다. 규칙 배포는 전체 교체이므로 일기장 규칙을 제거하거나 예전 규칙으로 덮어쓰지 마세요. 운영 한계·배포 안내는 [backend/README.md](backend/README.md)에 있습니다.

## 운영 주의

GitHub Pages와 Issue는 공개입니다. 학생 정보·일기·개인 문서·연락처·인증 정보는 제출하지 않습니다. 방문 기록은 GitHub 호스팅 정책이 적용됩니다. 공개 주소를 서버에서 방문하지 않아 등록 URL을 이용한 SSRF를 방지합니다. 운영자 사전 검토 없이 공개되며 링크의 내용·권한·안전성을 보증하지 않습니다. 보안·변경 사유·예외 처리·검증 한계는 [SECURITY-AUDIT.md](SECURITY-AUDIT.md)를 확인하세요.
